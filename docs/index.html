为什么抄一份 hosts 经常不管用

因为那份 IP 是在别人的网络上测出来的，而且测的方法本身就有问题。

1

测速位置不对

多数项目在 GitHub Actions 的海外机器上测，测的是「机房 → GitHub」，跟你的宽带没有任何关系。

2

测速指标是假值

它们测 TCP 握手。国内这个握手常被中间设备代答，1ms 就能「连上」，真正卡住的地方在后面的 TLS 握手。

3

写完就不管了

IP 是静态快照，GitHub 调度一变就失效。而且没人验证过写进去的 IP 到底能不能打开页面。

它做了什么不一样的事

四个环节，每一环都是针对上面三个问题设计的。

本机实测

裸 socket 直连，不走系统代理。测的是你这条线到 GitHub 的真实路径。

全链路计时

TCP 建连 + TLS 握手 + 首字节。实测 TLS 握手占总耗时一半以上，只测首字节会挑出最慢的 IP。

每域名 4 个 IP

单次连接成功率约 70%，写 2 个全挂概率 9%，写 4 个降到 0.8%。四个尽量来自不同网段。

写完再验一遍

按系统实际解析结果逐个域名跑完整链路，不通就把下一个 IP 换上来重写。

三步搞定

1

下载并解除锁定

只有一个 .bat 文件。如果提示「来自其他计算机」，右键 → 属性 → 勾选「解除锁定」。

2

双击，点「开始测速」

会弹一次 UAC —— 修改 hosts 必须管理员权限。等 15～25 秒。

3

点「写入 hosts」

自动备份、写入、刷新系统 DNS，然后逐个验证。看到「校验通过 10/10」就成功了。

最后一步：清浏览器 DNS 缓存

系统 DNS 刷新了，浏览器还有一层自己的缓存。不清的话还是走旧 IP —— 这是「换了 hosts 没效果」最常见的原因。

Chrome / Edge

打开后点 Clear host cache

chrome://net-internals/#dns

Firefox

打开后点 Clear DNS Cache

about:networking#dns

系统级（命令行）

Win + R → cmd → 粘贴回车

ipconfig /flushdns

⚠️ chrome:// 和 about: 是浏览器内部页，网页无法直接跳转（安全限制），所以这里给的是复制按钮 —— 粘到地址栏回车即可。最省事的办法其实是把浏览器完全关掉再开。

常见问题

换了 hosts 还是打不开？
  • 浏览器 DNS 缓存没清 —— 见上面那一节，最常见
  • hosts 里有重复条目，别的工具写的排在前面抢走了解析
  • IP 已经失效，重新跑一次工具
  • 网络环境变了：换 WiFi、开代理、运营商调整
  • 域名本身被污染（如 gist.github.com），hosts 解决不了
为什么每次结果都不一样？

因为网络本身在变。同一个 IP 间隔两分钟测，TLS 握手可能从 447ms 变成 2424ms。工具只是如实反映了当前状况。

安全吗？会改别的东西吗？
  • 只改 hosts 里 # === GitHub IP BEGIN === 到 END 之间的内容
  • 写入前自动备份为 hosts.bak
  • 纯文本脚本，源码公开，无二进制文件
支持 Windows 7 吗？

需要 PowerShell 3.0 以上。Windows 7 请先装 WMF 5.1，工具会检查版本并给出中文提示。
