两种用法，先选一种

推荐方法一。方法二省事，但不是在你自己网络上测的，成功率低一档。

推荐方法一：Windows 单文件 .bat

下载一个 .bat 文件（不是安装包，不用解压、不用装依赖），双击运行 → 点「开始测速」等 15～25 秒。它在你自己的网络上把每个候选 IP 的完整链路测一遍，把真正能用的写进 hosts，写完再逐个域名验一次。

单次 TLS 连接成功率约 70%，所以每个域名写 4 个不同网段的 IP —— 全挂概率从 9% 降到 0.8%。任何一条能通，页面就能开。

系统要求：Windows 7 SP1 及以上（Win7 需先装 PowerShell 5.1），无需 .NET 以外的运行库。

只改动 hosts 里 # === GitHub IP BEGIN === 到 END 之间的内容，其它行不碰；写入前自动备份为 hosts.bak。

下载 L1-GitHub-Hosts.bat

方法二：在线实时 hosts 列表

什么都不用下载。打开列表，把现成的内容复制或下载下来，粘进系统 hosts 文件即可。

数据来自多个公开项目交叉验证，并按实测延迟分层排序。但它不在你这台机器上测，只能保证「大概率能用」，不能保证对你这根网线最优。

要粘贴的目标文件：

C:\Windows\System32\drivers\etc\hosts

适合临时应急、不想运行程序，或者 Win / Mac / Linux 用户。

点「写入 hosts」之后

测速完成后点一下「写入 hosts」，下面这四件事工具会自动做完，不用你再操作。

1
自动备份

先把当前 hosts 复制成 hosts.bak，只保留一份，每次写入覆盖，不会越积越多。

2
写入 IP

每个域名 4 个，尽量来自不同网段；只动 BEGIN / END 标记之间的内容，其它行不碰。

3
刷新本地系统 DNS

自动执行 ipconfig /flushdns，让新记录立刻生效，不用你手动敲命令。

4
逐个域名验证

按系统实际解析结果跑完 TCP + TLS + 首字节，不通就换下一个 IP 重写，最多试 3 轮。

右上角提示「已写入并校验通过（10/10 个域名）」就成功了。如果之后还是打不开，去下一节手动再刷新一次 DNS。

刷新 DNS

hosts 改完，系统里还缓存着旧的解析结果。先刷新本地 DNS，再看浏览器那一层。

① 本地 DNS 刷新（必做）

按 Win + R → 输入 cmd → 回车，把下面这行粘进去再回车。看到「已成功刷新 DNS 解析缓存」就完成了。

ipconfig /flushdns

② 浏览器自己的缓存（打不开时再清）

浏览器会单独缓存一份 DNS。如果刷新了系统 DNS 还是走旧 IP，再清这一层。

Chrome / Edge chrome://net-internals/#dns
Firefox about:networking#dns

网页不能直接跳转到 chrome://、about: 这类浏览器内部页（安全限制），所以这里只提供复制。粘到地址栏回车，再点页面上的 Clear host cache / Clear DNS Cache。最省事的办法其实是把浏览器完全关掉再打开。

为什么抄一份 hosts 经常不管用

因为那份 IP 是在别人的网络上测出来的，而且测的方法本身有偏差。

1

测速位置不对

多数项目在 GitHub Actions 的海外机器上测，测的是「机房 → GitHub」，跟你的宽带没有关系。

2

测速指标是假值

它们测 TCP 握手。国内这个握手常被中间设备代答，1ms 就能「连上」，真正卡住的地方在后面的 TLS 握手。

3

写完就不管了

IP 是静态快照，GitHub 调度一变就失效。而且没人验证过写进去的 IP 到底能不能打开页面。

方法一做了什么不一样的事

四个环节，每一环都是针对上面三个问题设计的。

本机实测

裸 socket 直连，不走系统代理。测的是你这条线到 GitHub 的真实路径。

全链路计时

TCP 建连 + TLS 握手 + 首字节。实测 TLS 握手占总耗时一半以上，只测首字节会挑出最慢的 IP。

每域名 4 个 IP

单次连接成功率约 70%，写 2 个全挂概率 9%，写 4 个降到 0.8%。四个尽量来自不同网段。

写完再验一遍

按系统实际解析结果逐个域名跑完整链路，不通就把下一个 IP 换上来重写。

常见问题

换了 hosts 还是打不开？
  • 本地 DNS 没刷新 —— 先执行 ipconfig /flushdns，最常见
  • 浏览器缓存没清 —— 清一次或把浏览器完全关掉重开
  • hosts 里有重复条目，别的工具写的排在前面抢走了解析。点工具里的「恢复初始」清干净再写入
  • IP 已经失效，重新跑一次工具
  • 域名本身被污染（如 gist.github.com），hosts 解决不了
两种方法可以一起用吗？

不要。方法二复制的内容自带独立的起止标记，和方法一写的那段是两套，同时存在会让同一个域名有多条记录、互相抢优先级。选一种就好；切换前把另一套删掉，或点工具里的「恢复初始」。

为什么每次结果都不一样？

因为网络本身在变。同一个 IP 间隔两分钟测，TLS 握手可能从 447ms 变成 2424ms。工具只是如实反映了当前状况。

安全吗？会改别的东西吗？
  • 只改 hosts 里 # === GitHub IP BEGIN === 到 END 之间的内容
  • 写入前自动备份为 hosts.bak
  • 纯文本脚本，源码公开，无二进制文件
支持 Windows 7 吗？

需要 PowerShell 3.0 以上。Windows 7 请先装 WMF 5.1，工具会检查版本并给出中文提示。
